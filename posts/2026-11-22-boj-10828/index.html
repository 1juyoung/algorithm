스택

push, pop, size, empty, top 명령 N개(N ≤ 10,000)를 처리하는 스택을 구현해.

문제 보러 가기 ↗

내 풀이

my solutionpython
 1n = int(input())
 2l = []
 3for i in range(n):
 4    l.append(list(map(str, input().split(" "))))
 5
 6s = []
 7
 8for i in range(len(l)):
 9    if l[i][0] == 'push':
10        s.append(l[i][1])
11    elif l[i][0] == 'pop':
12        if len(s) == 0:
13            print(-1)
14        else:
15            print(s.pop())
16    elif l[i][0] == 'size':
17        print(len(s))
18    elif l[i][0] == 'empty':
19        if len(s) == 0:
20            print(1)
21        else:
22            print(0)
23    else:
24        if len(s) == 0:
25            print(-1)
26        else:
27            print(s[-1])
시간 복잡도 개선 가능
O(N)
내 공간O(N)
최선 공간O(N)

명령마다 append, pop, len이 모두 O(1)이라 전체 O(N)이야. 다만 input()과 print를 1만 번씩 부르면 파이썬에서는 느려질 수 있어. 실제 실행 시간도 220ms가 나왔어.

내 풀이 요약

명령을 모두 리스트에 저장한 뒤, 리스트 s를 스택으로 써서 명령마다 바로 출력했어.

잘한 점

  • 파이썬 리스트의 append와 pop을 스택으로 정확히 썼어
  • 빈 스택일 때 -1, 0, 1 처리를 빠짐없이 했어

코멘트

대량 입력은 sys.stdin.readline

명령이 1만 개라 input() 대신 sys.stdin.readline을 쓰면 훨씬 빨라.

출력은 모아서 한 번에

결과를 리스트에 모았다가 '\n'.join으로 한 번에 출력하면 print 호출이 줄어.

map(str, ...)은 필요 없어

split()의 결과는 이미 문자열이라 str로 바꿀 필요가 없어.

range(len(l)) 대신 직접 순회

for cmd in l처럼 바로 돌면 l[i][0]처럼 인덱스를 반복해서 쓰지 않아도 돼.

이 문제에서 드러난 약점

입력 처리명령이 많은 문제에서 빠른 입출력을 쓰지 않았어.

더 나은 풀이

sys.stdin.readline으로 명령을 바로 읽어 처리하고, 출력은 모아서 한 번에 내보내.

better · O(N)python
 1import sys
 2input = sys.stdin.readline
 3
 4n = int(input())
 5stack = []
 6out = []
 7for _ in range(n):
 8    cmd = input().split()
 9    if cmd[0] == 'push':
10        stack.append(cmd[1])
11    elif cmd[0] == 'pop':
12        out.append(stack.pop() if stack else '-1')
13    elif cmd[0] == 'size':
14        out.append(str(len(stack)))
15    elif cmd[0] == 'empty':
16        out.append('0' if stack else '1')
17    else:  # top
18        out.append(stack[-1] if stack else '-1')
19print('\n'.join(out))
